**Quick Start — Repo setup & deployment**

This repository hosts a Vite + React + TypeScript app. It is built with `npm run build` and deployed to GitHub Pages using a GitHub Actions workflow (`.github/workflows/deploy.yml`).

**Repo layout**
- `index.html` — development entry (imports `/src/main.tsx`).
- `src/` — application source (TSX, components, styles, `src/main.tsx`).
- `dist/` — production build output (generated by `vite build`).
- `.github/workflows/deploy.yml` — CI workflow that builds and deploys `dist` to GitHub Pages.
- `CNAME` — custom domain (also written into `dist/CNAME` during predeploy).
- `docs/` — documentation (this file + `DEPLOYMENT-ISSUE.md`).

**How deployment works (current configuration)**
- Pushes to `main` trigger the `deploy.yml` workflow. It:
  1. Checks out the repo, installs dependencies, and runs `npm run predeploy` (build + add-domain).
  2. Uploads `dist` as an artifact.
  3. Downloads the artifact in the deploy job and uses the `upload-pages-artifact` + `deploy-pages` Actions to publish the artifact to GitHub Pages.
- GitHub Pages should be configured (Settings → Pages) to use **GitHub Actions** as the source so the Pages service serves the uploaded artifact rather than files from a branch.

**How to push changes / update the site**
1. Create a feature branch and commit your changes locally:

```bash
git checkout -b feature/your-change
# edit files
git add -A
git commit -m "feat: ..."
git push origin feature/your-change
```

2. Open a PR and merge into `main`.
3. Merging to `main` triggers the GitHub Actions workflow which will build and deploy the `dist` artifact to Pages.
4. To manually re-run a deployment, go to the Actions tab, open the workflow run, and click "Re-run jobs".

**Verification after a deployment**
- Visit your site (e.g., `https://pdf.jacobpclouse.net/`) and view source — the deployed `index.html` should reference `/assets/index-*.js` (the production bundle). If it references `/src/main.tsx`, the dev file is being served and the deployment is incorrect.
- Quick CLI checks:

```bash
curl -I https://pdf.jacobpclouse.net/src/main.tsx
curl -sL https://pdf.jacobpclouse.net/index.html | sed -n '1,80p'
```

**Why you ran into the MIME error and the gh-pages pitfall**
- Problem summary: Browsers refuse to execute raw `.ts`/`.tsx` files served with `application/octet-stream`. The error occurred because the site was serving the repository root `index.html` (dev) which imports `/src/main.tsx`.
- When you used the `gh-pages` branch (or deployed branch content directly) it was easy to accidentally publish the unbuilt `index.html` or mix built/unbuilt files. That causes the browser to request `/src/main.tsx` from the server and fail with a MIME type error.
- Switching to GitHub Actions + Pages artifact ensures the server serves the built `dist` output (JS bundles) rather than raw source files. After switching, avoid re-creating a `gh-pages` branch with repo-root files that Pages might prefer — that can restore the old behavior.

**Helpful scripts / commands**
- Build locally: `npm run build`
- Build + add domain (used by CI): `npm run predeploy` (runs `build` then adds `dist/CNAME`).
- Preview production build locally: `npm run preview` or serve `dist` with a static server: `serve -s dist -l 5000`.

**If you accidentally see the dev `index.html` on Pages**
1. Confirm Pages source is set to **GitHub Actions** (Settings → Pages).
2. Confirm workflow run completed successfully and that the `Deploy to GitHub Pages` step finished.
3. Clear any CDN or browser cache and wait a few minutes for Pages to update (and for TLS certificate issuance for custom domains).
4. Remove or do not recreate a `gh-pages` branch containing the dev `index.html` — it can confuse Pages if the repo settings point to branch content.
